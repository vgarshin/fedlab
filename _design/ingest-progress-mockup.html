D · How it works (implementation already in the repo, not deployed)

  • Worker (core/stages/ingest.py): new IngestProgress counters — bytes of source zip downloaded (boto3 callback), files unpacked, teams registered. A ticker in pipeline.run_ingest publishes {"type":"ingest", …} to the run's Redis channel every 2 s (best-effort, like all progress events).
  • API: no change — the existing SSE relay (/api/runs/{id}/events) already forwards every published event.
  • Web (components/IngestBar.tsx): the run page parses ingest events into local state (no refetch storm — only real state events trigger refetches) and renders the strip while status === "ingesting".
  • Weights: overall % = download 45% · unpack 40% · register 15%, normalized over the phases that exist for this batch (a batch of unzipped folders has no download phase).
  • Tests: 81 passed (3 new: percent math, end-to-end totals on a real zip, ticker skipped without redis).
